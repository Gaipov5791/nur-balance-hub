# Подтверждение домена для отправки писем-напоминаний

## Почему текущая схема не работает

Сейчас напоминания отправляются через Resend с адреса `noreply@nur-balance-hub.lovable.app`. Но этот домен принадлежит Lovable — вы не управляете его DNS и не можете добавить DNS-записи (SPF, DKIM, DMARC), которые Resend требует для подтверждения. Поэтому Resend отклоняет все письма.

Подтвердить в Resend можно только **свой собственный домен**. Но есть способ проще — встроенная почта Lovable, которая берёт настройку DNS на себя.

## Рекомендуемый путь: встроенная почта Lovable

Lovable сам управляет SPF, DKIM и MX в делегированной подзоне вашего домена. От вас нужен только домен, которым вы владеете.

### Что нужно от вас

1. **Домен, который вам принадлежит** — например, `nur-balance.kz` или любой другой. Если домена нет, его можно купить: Project Settings → Domains → Buy new domain, или у любого регистратора.
2. Lovable запросит делегирование поддомена (например, `notify.nur-balance.kz`) на свои nameservers. Вы добавляете NS-записи у своего регистратора — и больше ничего: SPF, DKIM, MX настраиваются автоматически.

### Что произойдёт после настройки домена

1. Письма-напоминания начнут уходить с адреса вида `notify@nur-balance.kz` (или вашего домена).
2. Вся доставка, повторы, отписки и suppression обрабатываются на стороне Lovable — не нужно поддерживать очередь или таблицы.
3. Код отправки в `src/lib/reminders.server.ts` переключится на управляемую отправку Lovable вместо прямого вызова Resend.
4. Supabase Edge Function `send-transactional-email` больше не нужна — её заменит серверный маршрут в приложении.

### Шаги реализации

1. **Настроить домен** — открыть диалог настройки почты и указать ваш домен. Lovable покажет NS-записи для добавления у регистратора.
2. **Дождаться подтверждения DNS** — распространение занимает до 72 часов, обычно быстрее. Статус виден в Cloud → Emails.
3. **Переписать отправку** — переключить `sendJournalReminderEmail` в `src/lib/reminders.server.ts` на `sendLovableEmail` из `@lovable.dev/email-js` вместо прямого вызова Resend API. Установить пакеты `@lovable.dev/email-js`, `@lovable.dev/webhooks-js`, `@react-email/components`, `@react-email/render`, если их нет.
4. **Создать серверный маршрут отправки** — по образцу managed-почты, вызвать `sendLovableEmail` синхронно из серверного кода.
5. **Удалить старую Edge Function** — `supabase/functions/send-transactional-email/` больше не нужна после переключения.
6. **Проверить** — запустить крон-эндпоинт вручную, убедиться что письмо ушло. Проверить typecheck.

## Альтернатива: Resend с вашим доменом

Если вы хотите остаться на Resend:
1. Зайдите в Resend → Domains → Add domain.
2. Укажите свой домен (например, `nur-balance.kz`).
3. Resend покажет DNS-записи: SPF (TXT), DKIM (TXT/CNAME), DMARC (TXT), и опционально MX для приёма ответов.
4. Добавьте эти записи у своего регистратора домена.
5. Дождитесь статуса Verified в Resend (обычно 15–30 минут).
6. Измените `REMINDER_FROM_EMAIL` на адрес с вашим подтверждённым доменом, например `Nur Balance <notify@nur-balance.kz>`.

Этот путь требует больше ручной работы и самостоятельного управления доставкой, повторами и отписками. Lovable всё это берёт на себя.

## Технические детали

- Пакеты для managed-почты: `@lovable.dev/email-js@0.1.0` (именно эта версия), `@lovable.dev/webhooks-js`, `@react-email/components`, `@react-email/render`.
- Крон-эндпоинт `/api/public/cron/journal-reminders` остаётся без изменений — он вызывает `runJournalReminders`, которая уже вызывает `sendJournalReminderEmail`.
- Шаблон письма `renderJournalReminderHtml` в `src/lib/reminder-email.ts` переиспользуется как HTML-контент.
- Lovable Cloud не требуется для managed-почты, но домен — обязателен.

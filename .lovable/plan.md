# Шаг 2A: Авторизация, профили и защита маршрутов

## Цель
Перевести приложение с демо-входа на реальную авторизацию (email/пароль + Google), показывать реальный профиль пользователя, защитить личные разделы от гостей. Запись видео и хранилище — следующий подэтап (2B).

## Что уже сделано
- Lovable Cloud подключён, Supabase-интеграция на месте (клиент, auth-middleware, auth-attacher, client.server).
- `src/start.ts` уже регистрирует `attachSupabaseAuth` (bearer-токен для серверных функций).
- В БД есть таблицы `profiles` и `journal_entries` с RLS-политиками «только владелец», триггер авто-создания профиля при регистрации.

## Что нужно сделать

### 1. Безопасность БД (миграция)
- Отозвать публичный запуск `handle_new_user` у `PUBLIC`, `anon`, `authenticated` (сейчас исполняема всеми — подтверждено). Триггер продолжает работать: он вызывается механизмом событий от имени владельца, а не пользователями.

### 2. Настройка авторизации
- Включить авто-подтверждение email (вход сразу после регистрации, без письма) — выбрано пользователем.
- Включить Google-провайдер через Lovable-брокер (`supabase--configure_social_auth` google).
- Парольная защита по HIBP — включить.

### 3. Слушатель сессии и контекст роутера
- В `src/routes/__root.tsx` подключить один `onAuthStateChange`: при `SIGNED_IN`/`USER_UPDATED` — `router.invalidate()` + `queryClient.invalidateQueries()`; при `SIGNED_OUT` — только `router.invalidate()` (без рефеча, чтобы не было 401-шторма).
- Знак «Войти/профиль» в шапке должен зависеть от сессии (см. п.6).

### 4. Защита личных маршрутов (структура `_authenticated`)
Перенести личные страницы под гейт `src/routes/_authenticated/` (путь не меняется — pathless-лейаут не добавляет сегмент):
- Создать `src/routes/_authenticated/route.tsx` — гейт (`ssr: false`, `supabase.auth.getUser()`, редирект на `/auth` без сессии).
- Перенести: `journal`, `archive`, `buddy`, `rewards`, `care`, `therapists`, `settings` → `src/routes/_authenticated/`.
- `src/routes/index.tsx` — публичная посадочная: если есть сессия — редирект на `/dashboard`, иначе CTA «Войти». Полный дашборд переезжает в `src/routes/_authenticated/dashboard.tsx` (новый путь `/dashboard`).
- Нельзя создавать `src/routes/_authenticated/index.tsx`, пока существует `src/routes/index.tsx` (конфликт пути `/`).
- `src/routes/auth.tsx` остаётся публичным.

### 5. Реальная авторизация (`src/routes/auth.tsx`)
- Вход/регистрация через `supabase.auth.signInWithPassword` / `signUp` (авто-подтверждение включено — вход сразу).
- Google — через `lovable.auth.signInWithOAuth("google", { redirect_uri: window.location.origin })`.
- После входа — шаг онбординга (цель + жизненный статус) пишется в `profiles` через серверную функцию `updateProfile`; если профиль уже `onboarded` — сразу на `/dashboard`.
- Восстановление пароля: `resetPasswordForEmail` + публичная страница `/reset-password` (форма нового пароля через `updateUser({ password })`).

### 6. Серверные функции (`src/lib/profile.functions.ts`, `src/lib/entries.functions.ts`)
Все через `requireSupabaseAuth` (действуют от имени вошедшего, RLS соблюдается):
- `getProfile` — профиль текущего пользователя.
- `updateProfile` — имя, цель, жизненный статус, PIN, онбординг.
- `getRecentEntries` — последние записи (для дашборда и архива).
- (Создание записи с видео — подэтап 2B.)

### 7. Подключение реальных данных (замена демо)
- `AppShell` (боковая панель и мобильное меню): имя и Nur-Coins из реального профиля; если гость — «Войти».
- `settings.tsx`: профиль, цель, статус — из БД, сохранение через `updateProfile`.
- `dashboard.tsx`: недавние записи и монеты из БД (пустое состояние, если записей ещё нет).
- `archive.tsx`: реальные записи пользователя (пока без видео-плеера — 2B).
- Страницы «Поддержка», «Советы», «Психологи», «Достижения» остаются на демо-контенте до следующих подэтапов (чат/подбор/награды).

## Проверка
- Регистрация по email → вход сразу → онбординг → `/dashboard` с реальным именем.
- Google-вход работает (через брокер).
- Гость, открывающий `/journal` — редирект на `/auth`.
- Выход: очистка кэша, редирект на `/auth`, Back не возвращает в личное.
- Мобильная и десктоп-навигация сохраняют все разделы.
- Проверить через браузерный скрипт: вход, редирект, профиль, выход.

# Раздел «Психолог»: текущее состояние и путь к реальной работе

## Что уже сделано

- Отдельный раздел «Психологи» с доступом только для авторизованных пользователей.
- Каталог из трёх специалистов: имя, специализация, опыт, стоимость, отметка «проверен», выбор карточки.
- Форма записи: имя, контакт, удобное время, запрос — с валидными полями и кнопкой отправки.
- Кнопка «Написать в чат» и подпись про оплату по ссылке от специалиста.
- Оформление в общем стиле приложения, работает на телефоне и десктопе, есть SEO-описание страницы.

## Чего пока нет (проверено по коду)

- Список специалистов зашит в код, в базе нет таблицы психологов — карточки нельзя добавить или отредактировать без правки кода.
- Заявка никуда не сохраняется: нажатие «Отправить заявку» показывает только всплывающее сообщение, данные теряются.
- Кнопка «Написать в чат» тоже показывает только сообщение — переписки нет.
- Нет фото специалистов, расписания, свободных слотов, статусов заявки и истории обращений.
- Нет оплаты внутри приложения.

## Что предлагаю сделать для реальной работы

### Шаг 1. Каталог в базе (основа)
Переносим специалистов в базу: имя, специализация, опыт, описание, цена, языки, фото, признак «активен» и «проверен». Страница читает каталог из базы. Управление карточками — через раздел администратора (создать, отредактировать, скрыть).

### Шаг 2. Настоящие заявки
Заявка сохраняется в базе: кто отправил, к какому специалисту, контакт, удобное время, запрос, статус («новая», «в работе», «назначена», «завершена», «отменена»).
- Пользователь видит свои заявки и их статус в разделе «Психологи».
- Администратор видит все заявки в панели и меняет статус.
- Доступ настроен так, что чужие заявки не видны никому, кроме администратора.
- Понятные сообщения об успехе/ошибке и повтор при сбое.

### Шаг 3. Уведомление о новой заявке
Письмо администратору (и специалисту, если укажем его email) при поступлении заявки, чтобы никто не ждал ответа впустую.

### Шаг 4. Чат со специалистом
Переиспользуем механику живого чата из «Поддержки»: переписка привязана к заявке, мгновенная доставка, уведомления, возможность голосовых сообщений. Требует, чтобы у специалистов были свои учётные записи с ролью «психолог» и отдельным экраном заявок.

### Шаг 5 (по желанию). Расписание и оплата
Свободные слоты и запись на конкретное время; онлайн-оплата сессии картой. Оплату подключаем отдельно — нужен выбор платёжного провайдера и реквизиты.

## Технические детали

- Новые таблицы: `therapists` (публичное чтение только активных карточек) и `therapist_requests` (чтение своих заявок пользователем, полный доступ у роли `admin`), с RLS и явными GRANT.
- Роль специалиста добавляется в существующий `app_role` (`therapist`), проверка через `has_role`.
- Чтение каталога — публичным серверным клиентом; создание и чтение заявок — server function с `requireSupabaseAuth`.
- Страница `src/routes/_authenticated/therapists.tsx` переходит с `src/data/demo.ts` на данные из базы; демо-массив `therapists` удаляется.
- Админ-экран заявок — рядом с существующей «Модерацией», по той же схеме доступа.
- Чат — повторное использование схемы `buddy_messages`/realtime и `MediaMessageRecorder`.

## Что нужно от заказчика

- Реальные анкеты психологов: имя, специализация, опыт, цена, фото, контакт.
- Кто обрабатывает заявки: администратор вручную или сами специалисты со своим входом.
- Нужна ли онлайн-оплата на этом этапе и через какого провайдера.
